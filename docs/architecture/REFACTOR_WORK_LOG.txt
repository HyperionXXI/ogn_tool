OGN Tool - Detailed Refactor Work Log
Date: 2026-03-13
Branch context: feature/rf-intelligence

Purpose
-------
This file documents in detail the architectural and structural refactor work
that was carried out on the RF analysis engine, analysis packages, network
intelligence modules, UI compatibility layer, and supporting documentation.

The goal of this work was not to change functional behavior, but to:

- reduce coupling
- remove architectural ambiguity
- consolidate canonical module paths
- separate analysis logic from engine orchestration
- stabilize typed contracts
- prepare the project for both batch/snapshot analysis and future streaming


1. High-level refactor strategy
-------------------------------
The refactor followed these principles:

1. Keep behavior stable.
2. Move logic before deleting compatibility paths.
3. Validate after each small batch:
   - python -m compileall src apps
   - pytest -q
   - lint-imports
4. Preserve public API stability where possible.
5. Prefer canonical domain-based module placement:
   - models = contracts
   - analysis = analytical/domain logic
   - engine = orchestration
   - storage = persistence
   - apps/ui = UI runtime

3. Processing mode decision
---------------------------
An explicit architectural decision was formalized:

Canonical mode:
- batch / snapshot

Future extension:
- streaming / incremental

This has direct consequences on the kernel:

Canonical kernel contracts:
- RFObservationVector
- RFAnalysisDataset
- RFAnalysisResults
- NetworkGraph

Adapter layer:
- analysis/streaming/rf_state_engine.py
- storage/network_graph_store.py

This means the main engine remains deterministic, finite-dataset oriented, and
UI-friendly, while streaming remains an integration layer that can later feed
snapshot datasets into the canonical engine.


4. Typed graph model introduction
---------------------------------
A canonical typed graph model was introduced:

- src/ogn_tool/models/network_graph_model.py

It now defines:

- NetworkNode
- NetworkEdge
- NetworkGraph

This replaced or formalized previous dict-like graph handling.

Integration work:

- analysis/network_graph/rf_graph_builder.py now builds and returns NetworkGraph
- analysis/network_graph/graph_metrics.py holds graph metric logic
- engine/network_graph_engine.py was updated to type its graph result
- storage/network_graph_store.py now loads/saves/updates typed NetworkGraph

Compatibility consideration:

The graph model was kept mapping-friendly so existing callers relying on dict-
like access patterns would not break immediately.

6. Streaming adapter boundary
-----------------------------
The streaming adapter was made explicit.

Key work:

- src/ogn_tool/analysis/rf_state_engine.py originally contained the streaming
  implementation.

Later it was moved to:

- src/ogn_tool/analysis/streaming/rf_state_engine.py

And the old location was first kept as a compatibility wrapper, then removed.

Important addition:

- RFStateEngine.snapshot() -> RFAnalysisDataset

This established the streaming-to-batch boundary cleanly:

events
-> RFStateEngine
-> snapshot()
-> RFAnalysisDataset
-> RFAnalysisEngine.run(dataset)

This was the critical step that aligned future streaming support with the
canonical snapshot kernel.


7. UI architecture cleanup
--------------------------
The project originally had two overlapping UI trees:

- apps/ui/*
- src/ogn_tool/ui/*

This created namespace ambiguity and duplicated ownership.

Refactor performed:

1. Declared apps/ui as the canonical UI namespace.
2. Converted src/ogn_tool/ui modules into compatibility wrappers.
3. Migrated imports in runtime code to apps.ui.*.
4. Removed the old compatibility wrappers progressively, one file at a time,
   validating after each deletion.

11. RF engine split and orchestration cleanup
---------------------------------------------
The monolithic rf_engine was split earlier into:

- src/ogn_tool/engine/rf_dataset_builder.py
- src/ogn_tool/engine/rf_metrics_aggregator.py
- src/ogn_tool/engine/rf_pipeline_executor.py
- src/ogn_tool/engine/rf_engine.py

Goal:
- separate orchestration responsibilities
- reduce monolithic engine size
- isolate data shaping / aggregation / execution

The public engine remained stable:

- RFAnalysisEngine.run(...)
- RFAnalysisEngine.run_from_observations(...)
- build_analysis_dataset(...)

The public fa?ade was intentionally left for later cleanup, while deeper
analysis leakage was removed from transitional helpers first.


12. Engine purification work
----------------------------
This was the last major architectural cleanup phase.

12.1 rf_engine_network.py
Originally contained network-domain logic:

- build_radio_events
- build_station_reception
- compute_coverage_redundancy
- compute_blind_zones
- compute_station_overlap

These functions were moved into canonical analysis/network_metrics modules.

rf_engine_network.py was reduced to:

- compatibility re-exports
- inspect_zone_impl (still engine-state dependent)

This removed a clear domain-logic leak from engine/.

12.2 rf_engine_dataset_builder.py
Originally contained substantial analytical logic mixed with legacy dataset
assembly.

Progressive extraction removed:

- directional diagnostics
- shadow map preparation
- station metrics dataframe logic
- network metrics summary logic
- coverage grid enrichment
- signal-quality summary logic
- direct RFDiagnosis orchestration

These pieces were moved into analysis-level helpers:

- build_directional_diagnostics
- build_station_metrics
- build_network_metrics
- enrich_coverage_grid
- summarize_signal_quality
- evaluate_rf_diagnosis

What remains in rf_engine_dataset_builder.py now is mostly:

- legacy dataset assembly
- compatibility dataset dict shaping
- orchestration of analysis helpers

That makes it a transitional assembler rather than a hidden analysis module.

12.3 rf_engine_observations.py
Originally contained:

- observations_to_rows(...)

This helper was moved to:

- analysis/normalization/observation_rows.py

Then the engine shim was removed entirely after import migration.

12.4 rf_engine.py
This file was intentionally left mostly untouched during the last phase.
Reason:

- it is the public fa?ade
- touching it earlier would create higher-risk API churn

Current status:

- acceptable as orchestrator
- still legacy-friendly
- to be considered only after dict-dataset compatibility is intentionally
  reduced

17. Current stop point and remaining work
-----------------------------------------
The refactor was intentionally stopped at a stable point.

Why stop here:

- the core architectural leakage has been addressed
- further changes would start impacting legacy dict-dataset compatibility
- the remaining cleanup is no longer purely structural

What remains as deliberate technical debt:

1. rf_engine_dataset_builder.py
   Still a transitional assembler for the legacy dataset dict path.

2. rf_engine.py
   Still the public compatibility fa?ade.

3. Legacy dict dataset API
   Still present because UI/services/compat flows still depend on it.

4. Local untracked analysis artifacts
   Not part of the code refactor:
   - ogn_tool.svg
   - repo_tree.txt
   - symbols.txt
   - tree.txt


18. Recommended next directions
-------------------------------
After this work, the project is at a decision point.

The next steps should no longer be blind structural cleanup.

Three sensible directions remain:

Option A - Reduce legacy dataset dict API
- gradually replace dict dataset consumers
- stabilize typed-only engine outputs

Option B - Freeze and document
- consolidate docs further
- document remaining transitional engine pieces
- declare compatibility boundaries explicitly

Option C - Resume feature work
- network intelligence
- coverage planning
- streaming adapters
- UI feature integration

The architectural refactor itself is now in a stable and defensible state.


19. Final summary
-----------------
In practical terms, the work achieved the following:

- established canonical architecture documentation
- formalized the processing-mode ADR
- introduced and integrated a typed NetworkGraph model
- added validation to core contracts
- made streaming an explicit adapter layer
- removed the obsolete ogn_tool.ui runtime namespace
- cleaned a large number of compatibility wrappers
- canonicalized analysis into clear subpackages
- moved graph/tabular network logic into analysis
